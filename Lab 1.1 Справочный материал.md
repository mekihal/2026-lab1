## 2. Принципы L2/L3 адресации и пересылки

При формировании пакета стек протоколов узла-отправителя определяет тип доставки:

### 2.1. Прямая vs Косвенная доставка
* **Прямая пересылка (Direct Delivery):** если узел-назначение находится **в той же** IP-подсети, что и отправитель. Кадр формируется с MAC-адресом непосредственного получателя (`Target Host MAC`).
* **Косвенная пересылка (Indirect Delivery):** если сеть назначения **отличается** от сети отправителя. Отправитель не может передать кадр напрямую, поэтому кадр формируется с MAC-адресом своего **шлюза по умолчанию** (`Default Gateway MAC`).

### 2.2. Изменение заголовков при маршрутизации (Hop-by-Hop)
* **IP-заголовок (Layer 3):** `Source IP` и `Destination IP` в стандартных условиях остаются **неизменными** от начального отправителя до конечного получателя.
* **Ethernet-заголовок (Layer 2):** `Source MAC` и `Destination MAC` **перезаписываются заново** на каждом L3-маршрутизаторе при переходе из одного сегмента сети в другой.

## 3. Статическая маршрутизация

### 3.1. Общий шаблон команды
```text
Router(config)# ip route <СЕТЬ_НАЗНАЧЕНИЯ> <МАСКА> <NEXT_HOP_IP | ВЫХОДНОЙ_ПОРТ> [АДМ_ДИСТАНЦИЯ]
```
* **Рекурсивный маршрут (Recursive):** маршрут, в котором указан только IP-адрес следующего перехода (`Next-Hop IP`). Маршрутизатор выполняет рекурсивный поиск по таблице, чтобы связать этот IP с выходным интерфейсом.
* **Маршрут по умолчанию (Default Route):** задается сетью `0.0.0.0` с маской `0.0.0.0`.

---

### 3.2. Алгоритм расчета агрегированного маршрута (Route Summarization)

Чтобы объединить несколько маршрутов в один с **максимально узкой маской**:

1. Запишите адреса объединяемых сетей в двоичном виде (достаточно расписать октет, в котором начинаются различия).
2. Найдите количество **общих бит слева направо**, которые совпадают во всех сетях.
3. Количество совпадающих бит определяет новую длину префикса маски (`/длина`).
4. Все биты после границы совпадения обнуляются — получается адрес суммарной подсети.

> **Пример:** Объединение сетей `10.1.4.0/24` и `10.1.6.0/24`:
> * `4` в 3-м октете: `0000 0100`
> * `6` в 3-м октете: `0000 0110`
> * Общие биты: `0000 01` (первые 6 бит октета совпадают).
> * Длина суммарной маски: 8 бит (1-й октет) + 8 бит (2-й октет) + 6 бит (3-й октет) = `/22` (`255.255.252.0`).
> * Адрес суммарной сети: `10.1.4.0/22`.

---

### 3.3. Плавающий статический маршрут (Floating Static Route)
* **Административная дистанция (Administrative Distance / AD)** определяет приоритет источника маршрута (чем **меньше** число, тем маршрут надежнее).
* По умолчанию статический маршрут имеет **AD = 1**.
* Если задать статическому маршруту AD выше (например, `10`), он станет **плавающим (резервным)**: маршрутизатор не поместит его в активную таблицу маршрутизации до тех пор, пока доступен основной маршрут с меньшим значением AD.

## 4. Команды проверки и отладки

```text
! Проверка интерфейсов и их статуса
show ip interface brief

! Просмотр таблицы маршрутизации
show ip route

! Просмотр таблицы MAC-адресов на коммутаторе
show mac address-table

! Просмотр ARP-таблицы на сетевом оборудовании
show ip arp

! Очистка ARP-таблицы на оборудовании Cisco
clear arp-cache

! Просмотр и очистка ARP-таблицы в командной строке ПК (Command Prompt)
arp -a
arp -d
```
